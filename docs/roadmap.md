# 通用嵌入式架构学习路线

## 学习方法

围绕一个模拟传感器终端逐步练习：周期采样、校验数据、维护状态、处理命令和输出结果。先使用电脑模拟输入，再按需要接入开发板。

各开源项目的入口见 [源码阅读指南](reading-guide.md)，固定版本见 [版本清单](../sources.lock.json)。每阶段阅读少量相关文件，完成一个可以验证的结果。

## 1. 模块接口与数据所有权

参考 littlefs 的配置回调、实例状态和设备接口。

练习：定义传感器读取接口，约定单位、有效性、时间戳与错误。分别提供模拟输入和设备输入实现，让数据校验和告警规则使用同一份接口。为业务状态指定维护者，其他模块读取复制出的快照。

完成标准：更换输入实现后，核心规则无须修改；多个模块实例互不干扰。

## 2. 硬件与系统适配

参考 littlefs 的可替换回调和 Zephyr 示例的应用、驱动及板卡组织。

练习：隔离时钟、存储与通信设备能力。核心逻辑只依赖必要接口，平台实现由构建与启动装配选择。模拟字节流输入，验证组帧、校验和协议解析。

完成标准：更换板卡主要调整适配与配置，编解码器可以在电脑上独立验证。

## 3. 任务通信与资源管理

参考 FreeRTOS 的任务/队列 API、queue.c，以及 InfiniTime 的任务消息链路。

练习：按周期、阻塞和响应需求安排执行上下文。明确共享状态的写入者、跨任务同步和缓冲区生命周期。为队列规定容量与拥塞策略，区分周期样本和控制命令。

完成标准：能够解释哪些调用会等待、谁负责超时，以及如何避免拥塞阻断所有处理。

## 4. 异步状态机

参考 QP/C 的 blinky、dpp、defer 和测试示例。

练习：为通信设备定义初始化、连接、就绪、等待应答、故障与恢复状态。处理重复请求、取消、超时、断开和迟到应答。设备实现执行 I/O，状态机维护业务行为。

完成标准：固定事件序列产生预期状态与输出；更换设备实现时保留业务接口。

## 5. 固件升级与恢复

参考 MCUboot 的设计文档、bootutil、平台实现和模拟器。

练习：追踪镜像生成、接收、校验、兼容检查、安装、启动与确认。选择一种安装策略，列出持久状态，并研究每个中断点的恢复行为。

完成标准：形成升级操作步骤、状态图和故障恢复表，并说明恢复机制需要的分区与 Bootloader 支持。

详细内容见 [固件升级学习路线](firmware-upgrade-study.md)。

## 6. 工程装配与验证

参考 Zephyr 示例的构建配置和 QP/C 的主机测试组织。

练习：分别管理板卡能力、产品功能、协议版本与用户设置。显式选择依赖实现，用模拟输入验证编解码器、状态模型和状态机。记录替换平台或增加功能时的修改范围。

完成标准：变化集中在对应职责的模块中；核心行为能够脱离真实硬件验证。

## 专项阅读

- lwIP：网络接口、OS 适配、线程模型与缓冲区所有权。
- InfiniTime：完整产品的初始化、控制器及任务协作。
- LVGL：显示/输入适配、控件事件与对象生命周期。
