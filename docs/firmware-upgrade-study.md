# 通用固件升级学习路线

## 学习目标

理解从镜像生成到设备安装与启动的完整过程，并区分传输、校验、平台兼容、存储操作和恢复策略。通过 MCUboot 源码与模拟器研究这些职责的边界。

## 1. 阅读入口

以下路径相对于 sources/mcuboot/：

| 入口 | 学习内容 |
| --- | --- |
| docs/design.md | 镜像格式、安装策略与持久状态 |
| boot/bootutil/ | 镜像处理与升级核心 |
| boot/zephyr/ | 平台接入、Flash 适配与启动动作 |
| sim/README.rst、sim/tests/ | 模拟 Flash、升级中断与恢复验证 |
| docs/imgtool.md、scripts/imgtool.py、scripts/imgtool/ | 镜像生成与签名工具链 |

## 2. 正常升级流程

选择一个公开示例与安装策略，记录：

1. 使用的源码版本、工具链与构建配置。
2. 镜像生成命令、格式和包含的组成部分。
3. 目标平台、分区布局、Bootloader 及组件兼容条件。
4. 接收、暂存、校验和安装的完整过程。
5. 结果记录、重启、启动检查及版本确认。

完成标准：能够根据公开示例复现一次正常流程，并说明每个阶段的数据与资源如何交接。

## 3. 分清校验职责

| 职责 | 要验证的问题 |
| --- | --- |
| 接收 | 长度、超时、断线、重复输入和暂存空间 |
| 格式解析 | 标识、字段范围、偏移/长度和格式版本 |
| 完整性 | 校验覆盖范围与传输/存储损坏 |
| 真实性 | 签名、发布者身份与验证失败行为 |
| 兼容性 | 硬件、分区、镜像及组件版本关系 |
| 安装策略 | 更新对象、顺序、持久状态与成功条件 |

CRC 完整性检查与签名真实性检查承担不同职责。按示例采用的包格式分别理解与验证。

## 4. 升级状态与模块边界

可使用下列状态草案组织练习：

```text
空闲 → 接收 → 校验 → 兼容检查 → 准备资源 → 安装
                                           ↓
                              记录结果 → 重启 → 启动检查
```

每阶段约定成功、错误、超时、取消和清理行为。接收通道提供包或接收结果；升级协调模块管理流程；存储适配执行硬件操作；Bootloader 负责对应策略下的启动选择与恢复。展示模块读取进度并发出请求。

完成标准：升级核心可以接入模拟接收和模拟存储，流程不依赖特定界面或网络通道。

## 5. 故障与掉电恢复

| 中断点 | 要研究的行为 |
| --- | --- |
| 接收未完成 | 识别不完整包，清理或继续接收 |
| 格式、校验或兼容失败 | 返回错误，保留可运行版本 |
| 资源准备失败 | 恢复已经停止的服务 |
| 擦除/写入期间掉电 | 识别持久状态，执行恢复策略 |
| 写入完成但结果未记录 | 判断完成程度，避免错误重复安装 |
| 新固件启动失败 | 启动检查、回退或恢复入口 |
| 多组件只更新一部分 | 兼容处理与恢复更新 |

下载断点续传与安装期间的掉电恢复是不同问题。A/B、试运行确认和自动回退需要相应分区、Bootloader 与状态记录支持；按所选策略分别研究。

练习：使用模拟 Flash 的读写/擦除限制逐步注入故障，观察重启后的处理。记录已验证行为与平台假设。

## 完成标准

- 一份可以复现的构建、镜像生成、安装和版本验证步骤。
- 一张模块依赖图与升级状态图。
- 一份组件兼容关系与故障恢复表。
- 明确接收、校验、协调、存储和启动各自的职责。
